# 标书响应与问题排查（bid-respond）

## 场景 A：招标文件 → 如何响应

1. 用户提供招标文件路径（优先放入 `docs-vault/tenders/`）或粘贴关键条款。  
2. 对**用户点名的章节/星号项**逐条处理；默认先处理：资格、技术参数、实施、服务、安全/信创、评分办法。  
3. 每条输出：

```markdown
| 条款摘要 | 响应策略 | 建议写法要点 | 库内证据 | 风险 |
|----------|----------|--------------|----------|------|
```

4. **响应策略**统一口径：  
   - **完全响应**：直接引产品/实施方案已有能力  
   - **部分响应**：写清范围边界 + 可选增值  
   - **偏离**：只在用户明确要做偏离表时列出，标「需商务/法务确认」  
   - **不响应/待确认**：避免标书造假  

5. 检索克制：每 2～3 个相关条款合并 1 次 `rag_search`（产品名 + 条款关键词），证据不够再补。

## 场景 B：已有标书 → 可能有什么问题

按清单审阅（用户贴标书文本或路径）：

1. **无证据承诺**：写了库内不存在的参数/案例/资质  
2. **参数抄错**：与产品说明/参数表不一致（尤其数字、协议、点位、并发）  
3. **漏响应**：招标星号/废标项未回应  
4. **过度承诺**：工期、驻场、定制范围超出实施方案惯例  
5. **格式与一致性**：产品名称、版本、公司信息前后不一致  
6. **安全合规**：等保/信创/数据脱敏表述与方案冲突或空缺  

输出：

```markdown
## 问题清单（按严重级别）
| 级别 | 位置/原文摘录 | 问题 | 建议改法 | 依据 |
|------|---------------|------|----------|------|

## 废标高风险项（若有）
## 修改优先级（Top 5）
```

严重级别：**致命（可能废标）/ 高 / 中 / 低**。

## 禁止

- 建议标书虚构检测报告、案例、参数  
- 在未读条款时编「标准响应模板」冒充针对性响应  
- 把竞品未核实数据写进我方标书  

## 交付默认

- Markdown 表格，可直接贴进 Word  
- 所有「满足」必须能指到 `docs-vault` 出处
