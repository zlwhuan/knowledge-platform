# 参数符合性对照（param-match）

目标：输出**可交付的对照结论**（满足 / 部分满足 / 不满足 / 待确认），而不是泛泛介绍产品。

## 输入

用户提供或指定其一：

- 医院/客户参数表（Excel/Word/邮件粘贴）
- 招标参数条款
- 口头要求清单

我方依据：`docs-vault` 中产品说明、参数表 xlsx、实施方案、竞品与历史标书摘录。

## 快速流程

1. **抽取要求**：把医院要求整理成表格行（指标名 | 要求值 | 强制/加分 | 出处）。
2. **检索我方**（每条关键参数优先 1 次 `rag_search`）：  
   - `产品名 + 参数名/模块名`  
   - 必要时 `doc_type=products`  
   - 参数表 Excel 命中后用 `path` 回读片段。
3. **判定**（只基于库内证据）：

| 结论 | 含义 |
|------|------|
| 满足 | 库内有明确同等/更优参数或功能描述 |
| 部分满足 | 部分指标支持，或需配置/版本/定制 |
| 不满足 | 库内明确不支持或参数低于要求 |
| 待确认 | 库内找不到，或表述含糊需产品/研发确认 |

4. **输出对照表**（核心交付物）：

```markdown
## 参数符合性结论
总体：满足 X 项 / 部分 Y 项 / 不满足 Z 项 / 待确认 W 项
风险摘要：（最多 3 条）

| # | 医院要求 | 我方情况 | 结论 | 依据 |
|---|----------|----------|------|------|
| 1 | … | … | 满足/部分/不满足/待确认 | `path` § … |

## 建议动作
- 不满足项：偏离说明 / 替代方案 / 合作伙伴
- 待确认项：找谁确认、问什么
```

## 禁止

- 无库内依据擅自写「满足」
- 把「可定制/可开发」写成「已具备」
- 忽略强制项（*）与星号条款
- 输出没有出处的参数数字

## 何时可加检索轮次

- 同一指标 2 个产品/版本要对比时，各搜 1 次  
- 招标星号条款允许再补 1 次定向检索  
其余保持快答。
